# Releases of the PC game and what differs between them

Compared with [tools/builddiff.py](../tools/builddiff.py) (file by file, then per item with the project's parsers) and
[tools/glyphmatch.py](../tools/glyphmatch.py) (reads another language's text by matching its font glyphs against the English
font). All releases below are supported by the port; `src/datafiles.h` (generated by `tools/mkmanifest.py`) holds the
English manifest plus every file in which the others differ or that they lack, and `--verify` names the release a copy
belongs to.

Also on archive.org but not examined: the Portuguese (Portugal, Playgames) release, a German one (only inside a scene release
collection), and the UK 2004 budget re-release (its file listing matches 1.00). No French release was found.

## 1. The exe did not change

The Brazilian `Woody.exe` (InstallShield `data1.cab`, `tools/unshield5.py`) is **byte-identical** to the English one
(SHA-1 `70944736…`, link date 2001-10-17). The later releases are a data update only, so the port needs no engine changes
for them. The Polish exe is wrapped in SafeDisc 2 (`secdrv.sys`, `drvmgt.dll`, `00000001.TMP` on the CD, a 2.4 MB `data1.cab`);
it was not unwrapped, since its data equals the Brazilian build apart from the text.

## 2. The February 2002 data (Brazilian and Polish alike)

- **K1A**: a gameplay fix. A new trigger volume (216, model 26, script slot 520) and a new block in object 392 that sets
  var 126 when Woody is in it; the peck-switch object 402 lost the matching test. The level geometry was reworked as well:
  K1A models 17, 18 and 23 gained polygons (42 → 222, 26 → 126, 160 → 284), `.col` and `.tex` changed.
- **Hubs** (KWS, SWS, WWS): three new script objects without code (marker instances of model 7/8 at the same three spots in
  every hub) and two moved markers (up to 267 units); `.col`, `.lit` and `.tex` changed.
- **W3D**: instance 736 moved 61 units along z; `.col` changed. The script is unchanged.
- **W1A, S1A**: one new empty script object and one more trigger volume, nothing that uses it.
- **Every `.ins`**: re-exported. Polygon order, denormal floats and junk in unused fields (e.g. `rot_tracks` of Woody's
  camera nodes 140/141 on unused animations) differ; builddiff reports them, they do not change what is drawn.
- **Every `.rck`**: the text and the font are in the release's language; sounds and images are identical (only the item's
  `reserved` word, a stale pointer of the packing tool, differs). The Common banks have 140 strings instead of 135: the five
  new ones (135..139) are PlayStation 2 memory-card messages that the PC game never shows.
- **Fonts** are generated per release and, in these two, per level (glyph order = first occurrence in the text). The port's
  own menu texts (Display, Controls) therefore find their letters by glyph shape: `font_letters` in `src/hud.c` hashes each
  glyph cell's alpha (FNV-1a of w, h, alpha) and looks it up in the English letters and the other CDs' accented and
  Cyrillic ones (HUD_TEXT.md 1, where the translations of those texts are described). A letter a level font lacks (the
  Brazilian and Polish ones have no `X`/`x`) is taken from the release's Credits font (§3).
- **Music.bf**: identical directory (49 entries); only `/Game/2D.wav` (W2D) is now 22050 Hz instead of 44100 Hz.
- **Logo/Cryo.hnm**: a different film, 512×384, stereo APC sound, flags `0xc0` (was 640×480 mono, `0x40`); the port's HNM
  player decodes and shows it. The Polish CD also has its own `Logo/Eko.hnm` (4.9 MB).

## 3. Spanish and Russian

Both installers (`data1.cab`) hold the same `Woody.exe` as English and Brazilian (SHA-1 `70944736…`); the Spanish CD root also
has an unrelated `woody.exe` and `JuegoPumaFinal.exe`, a cereal-brand Flash game.

- **Spanish**: the level data is 1.00's; only the text banks (every `.rck`) and `Logo/Cryo.hnm`, `Eko.hnm`, `Universal.hnm`
  differ. Its fonts lack `j`, `w`, `Q`, `Z`, `$` and `'`.
- **Russian**: the February 2002 data, equal to the Brazilian CD in every level, `Music.bf` and `Logo/Cryo.hnm`; its own text
  banks and `Logo/Eko.hnm` (7.3 MB). The text is Cyrillic in a 124-glyph font that still has most Latin letters. The CD has no
  `Data/Lang` (the language level, loaded only on the consoles), which the manifest records as missing for this release.
- Every release's Credits font is a superset of its level fonts with the full ASCII set; the port's own menu texts take the
  letters a level font lacks from it (docs/HUD_TEXT.md §1.5).

## 4. The Polish ISO on archive.org has three bit errors

`archive.org/details/woody_202201` (`WOODY.iso`, SHA-1 `40892dec…`, also uploaded as
`woody-woodpecker-wielka-draka-parku-buzza-buzzarda-pl-haslo-fasterus`) differs from the Brazilian CD in three more places,
each a single cleared bit 4 at offset `0x39d` of a 2048-byte sector: `K1A.tex` `0x132b9d`, `WWS.tex` `0x21db9d` (one texel each)
and `Music.bf` `0xc9beb9d` (one sample of `/Game/3R.wav`). The English and Brazilian CDs agree on those bytes, so this is a
read error of the rip, not a Polish change. It is harmless; the manifest accepts both versions of those files for Polish.
The ISO also carries a second primary volume descriptor (SafeDisc), which Windows `tar` cannot read; Windows mounting and
the port's own ISO reader (Joliet, `datasetup_posix.c`) can.
